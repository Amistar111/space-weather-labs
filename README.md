# Space Weather Labs

Лабораторный проект по курсу **Methods and models for multivariate data analysis** (ИТМО, 1 курс магистратуры).

**Команда 3:** Газизуллин Нияз · Марнова Амина · Лазебный Всеволод

## Датасет

[`juliensimon/space-weather-indices`](https://huggingface.co/datasets/juliensimon/space-weather-indices) — ежедневные индексы космической погоды, 25 471 строка, 34 колонки, период с 1957-10-01.

Источник данных — NOAA/GFZ: солнечная активность (радиопоток F10.7, числа Вольфа) и геомагнитный отклик (индексы Kp, Ap, Cp, C9).

## Постановка задачи

**Линейная регрессия:** предсказать геомагнитную активность `ap_avg` по солнечным показателям.

| | Переменные |
| --- | --- |
| Целевая | `ap_avg` |
| Предикторы — непрерывные | `f107_obs`, `f107_adj`, `f107_obs_center81`, `f107_obs_last81` |
| Предикторы — дискретные | `sunspot_number`, `bartels_day` (1–27), `bartels_rotation` |

### Три правила, которые нельзя нарушать

1. **Хронологическое разбиение train/test.** Это временной ряд: соседние дни сильно скоррелированы, 11-летний солнечный цикл задаёт длинный период. Случайный split утечёт будущее в прошлое и надует метрики.
2. **Никаких геомагнитных колонок среди предикторов.** `kp_*`, `ap_*`, `kp_sum`, `cp`, `c9`, `is_storm`, `storm_level` — это тот же отклик, что и целевая переменная. Их использование даёт утечку.
3. **Только наблюдения.** Даты в файле доходят до 2041 года — это прогнозы. Фильтровать по `data_type == 'observed'`.

## Известные дефекты данных

Проверено по статистике датасета:

| Дефект | Детали |
| --- | --- |
| Пропуски | 178 строк (0.7%) в блоке Kp/Ap/cp/c9; 342 в `storm_level`; в f107 и sunspot пропусков нет |
| Ошибки ввода | `f107_obs` max = 938.6 при физическом потолке ~300; сглаженное за 81 день max = 279.5 — доказательство брака в сырых замерах |
| Скошенность | `ap_avg`: среднее 12.8, максимум 280. `kp_sum`: среднее 170, максимум 670 |
| Дисбаланс | `is_storm`: 615 True против 24 856 False (2.4%) |
| Под вопросом | `is_storm = false` при `storm_level = G5` в первых строках — проверить распределение колонки |

## Работа с ноутбуками в git

`.ipynb` — это JSON, и при параллельной правке он даёт нечитаемые конфликты. Перед началом работы каждому:

```bash
pip install nbdime
nbdime config-git --enable --global
```

После этого `git diff` и `git merge` на ноутбуках показывают изменения по ячейкам, а не по сырому JSON.

Договорённость: **один ноутбук — один человек.** Общий код выносим в `src/`.
